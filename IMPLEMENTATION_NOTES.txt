BACKEND AND DATA

Private application records and notes now remain in jobs. Published links use
minimal publicProfiles documents and private transactional slug reservations.
Rules enforce verified-owner/admin access, active content, individual unexpired
profile reads, immutable creation timestamps, and atomic publication/rename/
deletion. Selected content is read in bounded groups and omits inaccessible
archived/deleted records without changing the requested order.

Models defensively decode legacy records and distinguish omitted copyWith
arguments from explicit null, so optional values can be cleared. Project case
study fields and availability are editable. Analytics is nonblocking and
deduplicated per link per service session; anonymous clients never write view
counters, and content edits preserve old counters.

The seed uses stable IDs, preserves matched legacy IDs and existing selections,
and runs as a dry run unless explicitly applied. Seed and migration scripts
validate content, refuse unknown/conflicting/orphan legacy data, recheck source
documents and collection membership in the committing transaction, and require
explicit project confirmation plus a fresh backup for real-project writes.
